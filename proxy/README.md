# 图片代理部署说明

## 为什么需要它

有些 AI 渠道（实测 aipais.de）生成图片完全正常，但结果图放在
`disk.aipais.de` 这类对象存储上，**响应里没有 `Access-Control-Allow-Origin`**。

浏览器出于安全限制读不到这种响应，表现就是：**生成成功了，却卡在取图，最后报"Failed to fetch"**。

这不是应用的 bug，也不是密钥或余额问题 —— 是对方服务端没开跨域。
我们无法改对方服务器，所以需要自己加一层转发。

## 部署（免费，约 2 分钟，不需要买服务器和域名）

1. 打开 https://workers.cloudflare.com/ ，用邮箱注册并登录
2. 点 **Create Worker**（首次会让你起个名字，随意）
3. 把本目录 `worker.js` 的**全部内容**替换掉编辑器里的默认代码
4. 点 **Deploy**
5. 复制页面上的地址，形如 `https://xxx.yyy.workers.dev`
6. 打开 App → 设置 → **图片代理** → 粘贴这个地址

免费额度每天 10 万次请求，个人修图完全用不完。

## 验证是否部署成功

浏览器直接打开：

```
https://你的地址.workers.dev/?url=https%3A%2F%2Fdisk.aipais.de%2F任意图片路径
```

能看到图片就说明成功了。

## 它是怎么接进去的

应用取图逻辑是**先直连，失败才走代理**：

- 正常渠道（返回 base64 或已开跨域的图床）走直连，速度不受影响
- 只有直连失败的才转发到你的 Worker
- 代理留空时行为与之前完全一致

代码位置：`src/core/ai/pipeline.ts` 的 `fetchResultBitmap()`。

## 安全说明

- 只允许转发 **https** 地址
- 只放行 **图片类型**响应，不能当通用代理用
- Worker 不记录、不存储任何图片和密钥
- 支持 `GET` 与 `HEAD`，其余方法一律拒绝
